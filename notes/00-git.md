# Git: ветки, merge, rebase, конфликты

## Модель
- Коммит = снимок файлов + ссылка на родителя. Хеш зависит от содержимого и от родителя.
- Ветка = подвижный указатель на коммит, не копия файлов.
- HEAD = на какой ветке я сейчас стою.

## Merge
- Соединяет две ветки, создаёт merge-коммит с двумя родителями.
- Fast-forward: если в целевой ветке нет новых коммитов, Git просто двигает указатель, без merge-коммита.
- История не переписывается — безопасно для общих веток.

## Rebase
- Переигрывает мои коммиты поверх другой ветки. Коммиты новые, хеши меняются (другой родитель).
- Двигает только мою ветку. Чтобы изменения попали в main, после rebase нужен merge (будет fast-forward).
- Итог по коду тот же, что у merge. Разница — история: rebase даёт прямую линию, merge — честную с развилками.
- Золотое правило: не делать rebase запушенных веток, с которыми работают другие.
- В жизни: `git pull --rebase`; в GitLab способ вливания задаётся настройкой Merge Request (merge commit / semi-linear / fast-forward, squash).

## Конфликты
- Конфликт = обе ветки поменяли одну и ту же строку после общего предка. Бывает и при merge, и при rebase.
- При rebase конфликт может быть несколько раз — коммиты применяются по одному.
- Маркеры: `<<<<<<< HEAD` ... `=======` ... `>>>>>>> ветка`. Убрать все маркеры, оставить нужное.

| Режим  | Решил конфликт | Закончить               | Отменить            |
|--------|----------------|-------------------------|---------------------|
| merge  | `git add файл` | `git commit --no-edit`  | `git merge --abort` |
| rebase | `git add файл` | `git rebase --continue` | `git rebase --abort`|

- Во время rebase НЕ делать `git commit` — только `--continue`.
- Не понимаю, где я — `git status`. В `.git` руками не лезть.

## Грабли
- `sed 's/a/b/'` — три слэша, иначе `unterminated 's' command`. `-i` правит файл, `g` — все вхождения.
- `git commit -m` без `-a` не берёт изменения, которые не добавлены через `git add`.
- `git rm` удаляет файлы, ветку удаляет `git branch -d` (`-D` — без проверки).
- `git checkout -b` создаёт ветку; переключиться — `git switch`.

## Полезное
- `git config --global alias.lg "log --oneline --graph --all"` — дерево веток.
- `git config --global core.editor nano`.
